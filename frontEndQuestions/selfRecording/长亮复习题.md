# 长亮->农行复习题

### 1. 介绍一下微前端
 **微前端** 是一种 **现代前端架构模式** ，它将复杂的大型单页应用拆分为一组 **小型、独立的、专注于特定功能或模块** 的应用，每个小应用都可以 **独立开发、测试和部署** 。

这种架构的主要优势包括：

 **模块化开发** ：每个微前端组件可以由不同的团队独立负责，提高了开发效率和代码复用。

 **易于维护** ：当某个部分需要更新时，只需修改对应的微前端模块，而不会影响到整个应用程序的其余部分。

 **渐进式增强** ：对于新旧浏览器支持不同的模块，兼容性较差的浏览器可以加载核心功能，性能更好的浏览器则加载更丰富的功能。

 **复用和版本管理** ：通过 **服务端渲染(SSR)** 或 **CDN分发** ，微前端组件可以在多个项目中共享，简化了版本管理和部署流程。

 **适应不同平台** ：微前端允许在不同的客户端（如Web、移动端）轻松地切换和组合组件。

### 2. 原型链对象间继承的主要机制
 **定义与工作原理** ：原型链允许一个对象继承另一个对象的 **属性和方法** 。这种继承**不是**通过**类的继承**实现的，而是通过**原型对象之间的链接**。
例如：当一个对象试图访问一个属性时，如果该对象自身没有这个属性，JavaScript会首先检查该对象的原型(即创建该对象的构造函数的prototype属性)，如果原型中没有该属性，则会继续查找原型的原型，以此类推，直到找到属性或者到达原型链的顶端(通常是null或Object.prototype)。

### 3. 组件通信emit的优缺点
优点：
 1. **灵活性**：子组件可以非常灵活的向父组件**传递任何数据**。
 2. **解耦合性**：子组件通过emit触发事件，父组件监听事件，实现了组件间的解耦，提高了组件的**独立性和复用性**。
 3. **响应式**：子组件传递给父组件的数据同样**具有响应式**，可以实时更新数据和视图，提高用户体验。

缺点：
 1. **事件命名冲突**：项目过大，组件过多，容易造成事件命名冲突，需谨慎管理。
 2. **跨级通信复杂**：emit通常只使用子组件传值给父组件的**跨度一级的组件通信**，多级组件通信如果用emit则会增加通信的复杂性。

### 4. 前端如何进行项目优化
1. **请求数量优化** ：合并脚本和样式表，CSS Sprites（CSS图像合并技术），拆分初始化负载，划分主域
2. **请求带宽优化** ：开启 GZip，精简 JavaScript，移除重复脚本，图像优化，将 icon 做成字体
3. **缓存利用优化** ：使用 CDN（内容分发网络），使用外部 JavaScript 和 CSS，添加 Expires 头，减少 DNS 查找，配置 ETag，使 Ajax 可缓存
4. **页面结构优化** ：将样式表放在顶部，将脚本放在底部，尽早刷新文档的输出
5. **代码校验优化** ：避免 CSS 表达式，避免重定向
6. 浏览器**缓存机制**的优点有：
   1. 降低服务器压力，减少请求次数。
   2. 提升性能，本地资源加载比请求服务器快。
   3. 减少带宽消耗，产生很小的网络消耗。

常见且有效的策略：
1. **优化图片和媒体资源：**
> - **压缩图片** ：使用专业的图像编辑工具或在线服务来减小图片的文件大小，同时保持视觉质量。
> - **选择适当的图片格式** ：如 GIF、PNG、JPEG 和 WebP，每种格式都有其适用场景，需要根据具体需求来选择。
> - **使用懒加载** ：对于非首屏或用户滚动后才能看到的图片，采用懒加载技术，只在需要时加载，以减少初始加载时间。
1. **优化代码和资源文件：**
> - **压缩和合并 CSS、JavaScript 文件** ：通过工具如 UglifyJS、Terser 等来压缩代码，同时合并多个文件以减少 HTTP 请求次数。
> - **使用 CDN** ：内容分发网络（CDN）可以确保用户从最近的服务器获取资源，从而加快加载速度。
> - **缓存** ：利用浏览器缓存机制，将资源缓存在本地，减少重复请求。
1. **减少 HTTP 请求：**
> - **合并请求** ：通过合并多个 CSS、JavaScript 文件或者通过雪碧图（CSS Sprites）合并小图标来减少 HTTP 请求的数量。
> - **使用 HTTP/2** ：HTTP/2 协议支持**多路复用**，可以在一个连接中并行处理多个请求，从而显著提高加载速度。
1. **优化服务器响应：**
> - **启用服务器端的 Gzip 压缩** ：压缩传输的数据，减少网络传输的带宽需求。
> - **优化数据库查询** ：减少不必要的数据库操作，优化查询语句，提高查询速度。
1. **使用异步和延迟加载：**
> - **异步加载** ：对于非关键资源，如广告、统计脚本等，可以使用异步加载方式，避免阻塞主线程。
> - **延迟加载** ：对于非首屏内容或用户交互后才需要的资源，可以延迟加载，提高首屏加载速度。
1. **代码拆分和按需加载：**
> - **代码拆分** ：将大型代码库拆分成较小的块或模块，根据需要加载，避免不必要的资源浪费。
> - **按需加载** ：根据用户的交互或路由变化，动态加载所需的代码和资源。
1. **优化前端渲染：**
> - **使用虚拟滚动** ：对于大量数据的列表或表格，使用虚拟滚动技术，只渲染视口内的数据，提高渲染性能。
> - **避免重绘和重排** ：通过优化 CSS 选择器和布局，减少浏览器的重绘和重排操作，提高渲染速度。

### 5. vite和webpack的区别
**1. 打包方式：**

Webpack 是一个传统的静态模块打包工具，通过构建一个完整的依赖图，将所有模块打包成一个或多个 bundle。

Vite 则采用了现代化的开发模式，利用ES模块原生导入的特性，在开发过程中只对需要的模块进行即时编译，而不是将整个项目打包成一个 bundle。

**2. 开发体验：**

在开发环境下，Vite 以快速的冷启动速度和热模块替换（HMR）为特点，能够在保存文件时快速更新相关模块，提供更好的开发体验。

Webpack 在开发环境下也支持热更新，但相较于 Vite，它的启动速度可能会慢一些。

**3. 构建速度：**

Vite 的独特之处在于使用了 ES 模块的原生导入方式，避免了传统的依赖图构建过程，因此在构建速度上更快。

Webpack 在处理大型项目时，由于需要构建完整的依赖图，可能会相对较慢。

**4. 插件生态系统：**

Webpack 有一个庞大且成熟的插件生态系统，提供了丰富的插件和加载器来满足各种需求，如代码分割、压缩、优化等。

目前，Vite 的插件生态系统相对较小，但它能够兼容大部分现有的 Rollup 和 Webpack 插件。

**5. 生产环境构建：**

在生产环境下，Webpack 能够做更多的优化和压缩工作，生成高度优化的静态资源文件，适用于复杂项目的打包需求。

Vite 在生产环境下会将所有模块预构建为静态文件，类似于传统的打包工具，以确保在浏览器中的兼容性和性能。

***综上所述***，Webpack 是一个功能强大且成熟的静态模块打包工具，适用于大型项目的构建和优化需求。而 Vite 则是一个以开发体验和构建速度为重点的现代化构建工具，在开发环境中具有更好的即时更新能力。选择使用哪个工具取决于项目的具体需求和个人偏好。

### 6. 事件委托
事件委托（Event Delegation）是JavaScript中一种常用的**优化技术**，用于简化和提高性能。它将事件监听器绑定在**父元素**上，而不是每个单独的子元素上。当事件发生在一个动态生成的元素（如列表项、按钮等）上时，利用**事件冒泡（Bubbling）**机制，浏览器会将该事件逐级上报到父元素，从而允许父元素捕获并处理来自所有后代元素的同一种事件。
例如，在一个动态添加和删除的ul元素中，我们可以只给ul绑定一个"click"事件，然后在事件处理函数内部判断触发事件的对象是什么，进而做出相应的处理。这样可以减少事件监听器的数量，尤其是在大量子元素的情况下，提高了效率。
事件委托的优势包括：
1. **减少内存消耗**：无需为每个新创建的元素都添加一个事件监听器。
2. **灵活性高**：适应动态内容的变化，只需改变父元素即可。
3. **提升性能**：减少了DOM遍历次数，特别是在大型页面中。

### 7. 事件冒泡和事件捕获
**事件捕获** ：事件捕获是**由外到内**的。在事件捕获阶段，事件会从 DOM 树的最外层开始，依次向下经过每个节点，并触发节点上的事件，直至到达事件的目标节点。
**事件冒泡** ：事件冒泡和事件捕获是**完全相反**的。事件冒泡是**由内到外**的，它是从目标节点开始，沿父节点依次向上，并触发父节点上的事件，直至文档根节点，就像水底的气泡一样，会一直向上。
 - 阻止事件冒泡和事件捕获： **event.stopPropagation()** 或者vue中 **@click.stop** 修饰符。

### 8. webpack的使用
**1. 解析入口文件：**

Webpack 会根据配置文件中的入口(entry)字段，找到项目的入口文件。

入口文件可以是一个或多个，Webpack 会从这些入口文件开始递归解析依赖关系。

**2. 构建模块依赖关系图：**

Webpack 会根据入口文件以及它们所依赖的模块，构建出所有模块之间的依赖关系图(dependency graph)。

在构建过程中，Webpack 会根据遇到的模块类型（如 JavaScript、CSS、图片等），使用相应的 loader 进行转换处理。

**3. 应用加载器(loader)和插件(plugins)：**

Webpack 支持使用各种加载器(loader)来处理非 JavaScript 类型的文件。

每个加载器都可以对特定类型的文件进行转换，例如将 Sass 文件转换为 CSS，将 ES6 代码转换为 ES5 代码等。

插件(plugins)则可以在打包过程中执行一些额外的任务，例如代码压缩、资源优化等。

**4. 生成输出文件(bundle)：**

在构建完成后，Webpack 会根据配置文件中的出口(output)字段，将所有模块打包成一个或多个输出文件(bundle)。

输出文件可以是 JavaScript 文件、CSS 文件、图片文件等，可以通过配置文件指定输出的文件名和路径。

**5. 优化和压缩：**

在生成输出文件之前，Webpack 可以对打包结果进行优化和压缩。

优化方面，Webpack 支持代码分割、懒加载等功能，以减少初始加载时间。

压缩方面，Webpack 可以通过插件来实现 JavaScript、CSS 和图片等资源的压缩，减小文件体积。

***最终***，Webpack 将所有模块打包成静态文件，可供浏览器加载和运行。Webpack 的强大之处在于它能够处理各种类型的文件，并利用加载器和插件来实现自动化的构建和优化过程。

### 9. 样式引入有几种方式
四种：
1. **行内样式**：标签内直接style使用。
2. **内嵌样式**：通过<style>标签内嵌使用。
3. **外部样式**：通过<link rel="stylesheet" type="text/css" href="mystyle.css">标签外链使用。
4. **导入样式**：通过@import语句在一个CSS文件中导入另一个CSS文件使用。

**优先级** ：!important > 行内样式 > ID选择器 > 类选择器 > 元素本身属性 > 通配符* > 继承属性 > 浏览器默认属性

### 10. JS中数组的方法
``` let arr = [1,2,3] ```
1. arr.join('-')：将数组串联：'1-2-3'， **会改变** 原数组。
2. push()和pop()：末尾新增和末尾删除， **会改变** 原数组。
3. unshift()和shift()：头部新增和头部删除， **会改变** 原数组。
4. sort()：排序， **会改变** 原数组。
5. reverse()：反转数组， **会改变** 原数组。
6. arr.splice()：可以实现删除、插入和替换， **会改变** 原数组。
  - 1. 删除：arr.splice(0,1)：从下标0开始截取1个，相当于删除第1项，原数组变为[2,3]。
  - 2. 插入：arr.splice(2,0,4,6)：从下标2开始截取0个，并在下标2开始添加4和6，原数组变为[1,2,4,6,3]。
    3. 替换：arr.splice(1,1,4)：从下标1开始截取1个，并在下标1开始添加2，完成替换，原数组变为：[1,4,3]。
7. arr.slice(0,2)：不改变原数组，截取数组下标(0,2)不包含2的数组：[1,2]。
8. arr.concat(4,[5,6])：添加到数组中：[1,2,3,4,5,6]。
9. indexOf()和 lastIndexOf()：查找对应元素元素首次/最后一次出现的下标。
10. forEach：遍历数组，无返回值。
11. map：遍历数组，有返回值。
12. some：遍历数组，有一项为true则返回true。
13. every：遍历数组，有一项为false则返回false。
14. filter：遍历数组，过滤符合条件的数据，返回一个新数组。

### 11. v-for 的 key
**key值**的作用是给元素添加一个唯一的标识符，提高vue渲染性能。可以依靠key,更准确, 更快的拿到oldVnode中对应的vnode节点。当数据变化的时候，vue就会使用diff算法对比新旧虚拟Dom。 如果遇到相同的key值，则复用元素。如果遇到不同的key值则强制更新。
